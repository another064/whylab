## 1. 要解决的问题

AI 已经能给出解释，但学习仍然断在四处：

1. 拿到答案，不理解答案背后的原理与前提。
2. 连续追问的推导过程散落在聊天记录里，无法长期沉淀。
3. 当下觉得懂了，几天后无法独立复述，也没有复习机制检验。
4. **每次对话都从零开始**：AI 不记得这个人上次卡在哪、常犯什么误解、什么讲法对他有效。

## 2. 产品定位

WhyLab 是一个**持续追问、持续巩固、并记住每个人思维方式**的学习 agent：

**提出问题 → 双向追问 → 保存知识 → 主动回忆 → 获得反馈 → 安排复习**
　　　　　　　　　　↘　　　　每一步的表现沉淀为「思维档案」　　　↙
　　　　　　　　　　　　思维档案反过来影响下一次的追问、讲解与复习

两个差异化能力：

| 能力 | 含义 |
| --- | --- |
| **双向追问** | 既能让用户追问 AI（解释模式），也能让 AI 追问用户（追问模式，苏格拉底式） |
| **思维档案** | 基于可观察的行为证据，记住每个人的追问倾向、反复误解、推理断点、有效讲法 |

## 3. 设计原则（约束技术方案）

1. 先理解，再记忆：支持追问机制、推导、反例与适用边界。
2. AI 辅助而非替代：鼓励用户自己解释、自己作答；追问模式下 AI 默认不直接给答案。
3. 用户掌握知识结构**与自己的档案**：AI 可提议节点、关系与思维模式，用户可确认、修改、删除。
4. 区分事实、解释与推测：尽量给出来源，明确不确定性。
5. 以真实表现更新状态：看过解释 ≠ 掌握，只有独立回忆才算证据。
6. **只记录行为，不评判人**：思维档案描述"这次推导缺少边界条件"，不写"你逻辑差"；不做人格或固定学习风格分类。
7. MVP 优先验证闭环：不引入知识图谱算法、多智能体系统。

## 4. 目标用户

- 追求原理的学习者：不满足于记公式，想沿一个问题持续深入。
- 需要巩固的学生：学过就忘，不知道该复习什么。
- 用 AI 自学的大学生/自学者：希望把文档、笔记与问答长期关联，并希望 AI 越用越懂自己。

## 5. 双追问模式

每个对话有一个当前模式，用户可随时切换；切换只影响之后的回合，历史消息保留原模式标记。

### 5.1 解释模式（`explain`，默认）

用户问，AI 答。

- AI 给出解释 + 最多 3 条追问建议（"这个结论依赖哪些前提？""什么情况下不成立？"）。
- 若思维档案显示用户**很少问某类问题**（如边界条件），追问建议优先补这一类。
- 若档案中有"有效讲法"（如类比先行），解释优先采用该讲法。

### 5.2 追问模式（`socratic`）

AI 问，用户答。适合"我想自己想明白"的场景。

一轮追问的流程：

1. 用户提出学习目标（如"我想弄懂闭包为什么能访问外部变量"）。
2. AI **不直接给答案**，先问一个诊断问题，了解用户现有理解。
3. 用户作答 → AI 判断：指出对的部分，对缺失或误解的部分**再追问一层**，必要时给提示。
4. 提示分三级逐步加强：`nudge`（方向提示）→ `hint`（关键线索）→ `reveal`（直接讲解该步）。
5. 用户达到目标或主动结束时，AI 生成**本轮小结**：用户自己说对了什么、哪一步卡住、最终结论。
6. 小结可一键保存为知识节点（`understanding` 类型，内容以用户自己的话为主）。

约束：

- 每轮最多追问 N 层（默认 6），超过则给出讲解并结束，避免无限盘问。
- 用户随时可点"直接告诉我"：本步切为 `reveal`，并记一条证据（不扣分，只记录卡点位置）。
- 追问前参考思维档案：已知用户常在某类步骤卡住，就在该步多问一层。

### 5.3 模式与复习的关系

- 每日复习本质上是"针对已保存知识的追问模式"，复用同一套反馈结构。
- 复习答错时，可从该题直接进入追问模式继续深挖。

## 6. 思维档案（Thinking Profile）

### 6.1 记录什么

只记录能从对话或复习中找到证据的行为模式：

| 类别 `category` | 含义 | 例子 | 主要证据来源 |
| --- | --- | --- | --- |
| `questioning` | 追问倾向 | 常问"为什么成立"，很少问"何时不成立" | 用户提问 |
| `misconception` | 反复出现的误解 | 把相关当因果；混淆值传递与引用传递 | 复习反馈、追问模式作答 |
| `reasoning_gap` | 推理断点 | 从定义到应用时常跳步 | 追问模式卡点、复习缺失点 |
| `effective_strategy` | 对他有效的讲法 | 类比先行后一次就懂 | 追问次数、后续复习表现 |
| `mastered` | 已能独立解释的概念 | 能独立讲清"词法作用域" | 复习 `good` / `easy` 记录 |

### 6.2 档案的生命周期

1. **提取**：一次对话会话结束或一次复习完成后，后台批量分析（不逐条消息分析），产出候选模式。
2. **候选**：状态 `proposed`，带置信度与证据链接，**不注入提示词**。
3. **确认**：用户在"我的思维档案"页确认 / 修改 / 驳回。同一模式被独立证据观察到 ≥ 3 次时，也可自动升为 `confirmed`，并通知用户。
4. **使用**：只有 `confirmed` 的模式会被注入对话、追问、复习反馈的提示词，每次最多注入与当前主题相关的 5 条。
5. **衰减**：长期（默认 60 天）无新证据的模式降低权重；`misconception` 在连续 3 次复习中未再出现时，提示用户"可能已克服"。

### 6.3 约束

- 每条模式必须能追溯到至少 1 条证据（消息或复习记录的片段）。
- 用户可查看、编辑、删除任一模式，或一键清空档案、暂停档案记录。
- 驳回的模式不再重复提议（相似描述去重）。
- 档案属于敏感个人数据：不在任何界面对外展示，不用于评分或排名。

## 7. MVP 范围

### P0（必须，构成完整闭环）

| 模块 | 功能 |
| --- | --- |
| 学习空间 | 创建空间、设置主题 |
| AI 对话 · 解释模式 | 多轮问答、上下文关联、追问建议 |
| AI 对话 · 追问模式 | 诊断提问、分层追问、三级提示、本轮小结 |
| 知识保存 | 保存问题 / 解释 / 个人理解（含追问小结）为节点 |
| 知识管理 | 列表、详情、编辑、删除、按空间筛选、简单搜索 |
| 每日复习 | 到期任务、隐藏答案的回忆界面、结构化反馈 |
| 复习调度 | 依据表现计算下次复习时间 |
| 思维档案（最小版） | 会话/复习后提取候选 → 档案页确认/驳回/编辑 → 已确认模式注入提示词 |
| 学习记录 | 学习历史与复习结果统计 |

### P1（闭环稳定后）

PDF 上传与文本提取、文档问答与来源引用、知识关系图（Vue Flow）、学习数据图表、思维档案的变化趋势与"已克服误解"回顾。

### P2（后续迭代）

本地模型（Ollama）、跨学习空间的模式迁移分析、更复杂的个性化策略。

### 非目标（第一版明确不做）

多人协作与社区、教务系统、全学科自动知识图谱、**人格分析与固定学习风格分类**（思维档案只记录有证据的行为，见 §6）、完整考试评分、自训练模型、多智能体系统、全自动知识结构重组、支付与订阅。

## 8. 非功能需求

- **可用性**：核心操作有明确反馈；AI 生成期间显示加载态；失败可重试；刷新后已保存内容仍在；复习完成立即更新状态。
- **性能**：本地开发页面加载 ≤ 2s；常规查询 ≤ 500ms；AI 回答支持流式输出；档案提取异步执行，不阻塞对话。模型响应时间不作绝对承诺。
- **成本**：档案提取按会话批量执行，单次会话最多 1 次提取调用。
- **数据与隐私**：学习记录与思维档案默认只属于当前用户；API Key 只存服务端；用户可删除自己的知识、记录与档案；接入云端模型前说明数据会发送到外部；本地库 ≠ 端到端加密。
- **可维护性**：前端 / 后端 / AI 服务 / 数据访问职责分离；复习算法与档案规则（升级、衰减）独立于提示词且为纯函数；AI 输出结构化并服务端校验；核心逻辑有自动化测试。

## 11. MVP 成功指标

不看页面数量或代码行数，只看闭环：

- 学习空间创建成功率、消息持久化成功率、节点保存成功率、复习完成率、反馈生成成功率；
- 用户能否在不看原答案的情况下解释关键概念；
- 用户是否愿意继续使用。

思维档案专项（验证"记住思维模式"不是宣传语）：

- **确认率**：候选模式被用户确认的比例（过低说明提取噪音大）；
- **针对性对照**：同一复习题分别在有/无档案条件下生成反馈，人工评判哪次更具体地指向用户的已知问题；
- **误解复发率**：已确认的 `misconception` 在后续复习中出现的频率是否下降。

在没有真实用户数据之前，不宣称"提升学习效率/记忆力"。

## 13. 界面设计稿带来的补充需求（V0.3）

| 设计里的东西 | 需求 | 落点 |

| 首页的问候、待回忆数、未完成的追问 | 汇总接口；用户可设置显示名 | `GET /api/today`；`users.display_name`（迁移 002） |
| "依赖：词法作用域（你已能讲清）" | 节点依赖与档案里"已掌握的概念"关联查询 | `GET /api/nodes/:id` 的 `dependsOn[].mastered` |
| 知识库"只看还没写理解的" | 节点列表支持该过滤条件 | `GET /api/spaces/:id/nodes?missingUnderstanding=1` |

### 13.1 界面层的约定

- **颜色只表示"谁说的"**：薄荷 = AI 说的 / 问的，可可 = 你写的 / 你说对的，黑巧 = 正文、主按钮、导航选中态。全部定义在 `client/src/styles/tokens.css`，组件不写死颜色。
- **断点**：< 768 底部标签栏、单列；768–1199 左侧导航，右侧栏落到内容下方；≥ 1200 导航 + 内容 + 右侧栏。回忆页是专注页，不显示导航；手机上的探究页用返回栏代替标签栏。
- **动效**：只用设计列出的几种（逐字出现、推理路径、卡片叠放、数字滚动、列表依次进入、点阵底纹、淡入），全部遵守系统"减少动态效果"设置。
- **看提示不扣分**：提示只记录"在哪一步需要帮助"，作为档案证据，不影响评分。

### 13.2 设计还没覆盖的（待补设计）

- 深色模式（`tokens.css` 已按变量组织，补设计后只改这一个文件）。
- 空状态：第一次打开、还没有任何知识时。当前实现用的是中性占位样式。
- 加载中、出错两种状态（§8 明确要求）。当前实现用的是骨架屏和"重试"按钮的中性版本。
