- 产品类型：AI 辅助学习平台

## 1. 要解决的问题

AI 已经能给出解释，但学习仍然断在三处：

1. 拿到答案，不理解答案背后的原理与前提。
2. 连续追问的推导过程散落在聊天记录里，无法长期沉淀。
3. 当下觉得懂了，几天后无法独立复述，也没有复习机制检验。

## 2. 产品定位

WhyLab 不是"聊天框 + 大模型"，而是把一次问答转化为可沉淀、可检验、可复习的学习过程：

**提出问题 → 获得解释 → 保存知识 → 主动回忆 → 获得反馈 → 安排复习**

## 3. 设计原则（约束技术方案）

1. 先理解，再记忆：支持追问机制、推导、反例与适用边界。
2. AI 辅助而非替代：鼓励用户自己解释、自己作答。
3. 用户掌握知识结构：AI 可提议节点与关系，用户可修改、删除、重组。
4. 区分事实、解释与推测：尽量给出来源，明确不确定性。
5. 以真实表现更新状态：看过解释 ≠ 掌握，只有独立回忆才算证据。
6. MVP 优先验证闭环：不提前引入学习画像、知识图谱算法、多智能体。

## 4. 目标用户

- 追求原理的学习者：不满足于记公式，想沿一个问题持续深入。
- 需要巩固的学生：学过就忘，不知道该复习什么。
- 用 AI 自学的大学生/自学者：希望把文档、笔记与问答长期关联。

## 5. MVP 范围

### P0（必须，构成完整闭环）

| 模块 | 功能 |
| --- | --- |
| 学习空间 | 创建空间、设置主题 |
| AI 对话 | 多轮问答、上下文关联、追问建议 |
| 知识保存 | 保存问题 / 解释 / 个人理解为节点 |
| 知识管理 | 列表、详情、编辑、删除、按空间筛选、简单搜索 |
| 每日复习 | 到期任务、隐藏答案的回忆界面、结果反馈 |
| 复习调度 | 依据表现计算下次复习时间 |
| 学习记录 | 学习历史与复习结果统计 |

### P1（闭环稳定后）

PDF 上传与文本提取、文档问答与来源引用、知识关系图（Vue Flow）、学习数据分析。

### P2（后续迭代）

本地模型（Ollama）、更复杂的学习行为分析与个性化策略。

### 非目标（第一版明确不做）

多人协作与社区、教务系统、全学科自动知识图谱、人格/学习风格分析、完整考试评分、自训练模型、多智能体系统、全自动知识结构重组、支付与订阅。

## 6. 非功能需求

- **可用性**：核心操作有明确反馈；AI 生成期间显示加载态；失败可重试；刷新后已保存内容仍在；复习完成立即更新状态。
- **性能**：本地开发页面加载 ≤ 2s；常规查询 ≤ 500ms；AI 回答支持流式输出；文档解析显示进度或失败状态。模型响应时间不作绝对承诺。
- **数据与隐私**：学习记录默认只属于当前用户；API Key 只存服务端环境变量；用户可删除自己的知识与记录；接入云端模型前说明数据会发送到外部；本地库 ≠ 端到端加密。
- **可维护性**：前端 / 后端 / AI 服务 / 数据访问职责分离；复习算法独立于提示词；AI 输出结构化并服务端校验；核心逻辑有自动化测试。

## 7. 验收要点（摘自 14 条测试用例）

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| TC-01 | 创建学习空间 | 保存成功并显示在首页 |
| TC-02 | 连续追问同一知识点 | 结合上下文回答 |
| TC-03 | 保存一条 AI 解释 | 生成正确知识节点 |
| TC-04 | 修改知识节点 | 持久化保存 |
| TC-05 | 删除知识节点 | 节点与关联复习任务被合理处理 |
| TC-06 | 从节点创建复习任务 | 出现在复习列表 |
| TC-07 | 未作答时查看答案 | 回忆界面不直接展示参考答案 |
| TC-08 | 提交完整回答 | 得到针对关键点的反馈 |
| TC-09 | 提交不完整回答 | 指出缺失内容，而非笼统评价 |
| TC-10 | 完成一次复习 | 生成历史并更新下次复习时间 |
| TC-11 | AI 接口报错 | 显示错误并允许重试 |
| TC-12 | 刷新页面 | 已保存记录仍存在 |
| TC-13 | 非法/缺失参数 | 后端校验并返回明确错误 |
| TC-14 | 越权读取他人数据 | 服务端拒绝（多用户版本） |

## 9. MVP 成功指标

不看页面数量或代码行数，只看闭环：

- 学习空间创建成功率、消息持久化成功率、节点保存成功率、复习完成率、反馈生成成功率；
- 用户能否在不看原答案的情况下解释关键概念；
- 用户是否愿意继续使用。

在没有真实用户数据之前，不宣称"提升学习效率/记忆力"。
